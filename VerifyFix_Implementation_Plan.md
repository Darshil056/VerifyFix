### 2. Token Optimization & Zero-Redundancy State Design

To avoid token waste and repeated LLM calls:
1. **Hierarchical State Passing:** The LangGraph `VerifyFixState` object stores outputs incrementally. When Agent 1 extracts a vulnerable code snippet, downstream agents only receive that isolated snippet and line range, never the entire diff or codebase.
2. **Deterministic Temperature Mapping:**
   * **Agent 1 (Discovery):** `Temperature 0.2` (Broad, factual vulnerability extraction).
   * **Layer 2 (RAG Synthesis):** `Temperature 0.1` (Strictly grounded factual context).
   * **Agent 3 (Critic / Fixture Generator):** `Temperature 0.0` (Purely deterministic syntax generation).
   * **Agent 4 (Senior Remediation):** `Temperature 0.4` (Structured natural language explanation).
3. **Early Pruning:** Agent 3 filters out obvious false positives before generating test fixtures, preventing unnecessary sandbox runs and API iterations.

#### 🚀 Phase 2: LangGraph State Machine & Flask Streaming Engine

**Objective:** Build the Flask execution server and formalize the LangGraph DAG state machine.

##### 2.1 LangGraph State Formalization
Define the core typed state in `backend/agents/state.py`:
```python
from typing import TypedDict, List, Dict, Any, Literal

class VerifyFixState(TypedDict):
    repo_owner: str
    repo_name: str
    branch_name: str
    target_diff: str
    candidate_vulns: List[Dict[str, Any]]      # Populated by Agent 1
    rag_context: Dict[str, str]                # Populated by Layer 2 RAG
    pruned_vulns: List[Dict[str, Any]]         # Filtered by Critic Agent Phase I
    generated_fixtures: Dict[str, str]         # Code generated by Critic Agent Phase II
    docker_status: Dict[str, str]              # State: SECURE | VULNERABILITY_CONFIRMED | HARNESS_ERROR
    harness_error_traces: Dict[str, str]       # Captured stderr traces for retry loop
    retry_count: int                           # Max retry loop limiter (e.g., max 3)
    final_remediations: List[Dict[str, Any]]   # Formatted by Senior Analyst Agent
    execution_step: str                        # Used for real-time frontend animation
```

##### 2.2 Flask Server-Sent Events (SSE) Engine
- Implement an SSE endpoint in Flask (`/api/scan/stream`) to broadcast real-time state changes and node transitions to Next.js as the DAG executes.

#### 🚀 Phase 3: Online ChromaDB RAG & Context Enrichment

**Objective:** Build an on-demand, targeted knowledge retrieval engine specifically for identified CWEs.

##### 3.1 Agent 1: Candidate Discovery Scanner
- Connect Flask to the Google Gemini 2.5 Flash API (`temperature=0.2`).
- Provide the diff and repo AST summary. 
- Prompt strictly enforces a JSON array response schema:
  ```json
  [
    {
      "cwe_id": "CWE-89",
      "vulnerability_name": "SQL Injection",
      "file_path": "routes/auth.py",
      "line_start": 42,
      "line_end": 48,
      "suspect_code": "cursor.execute(f'SELECT * FROM users WHERE user={user_input}')"
    }
  ]
  ```

##### 3.2 Dynamic Online RAG & Vector Injection
- **ChromaDB Client:** Initialize ChromaDB using local disk storage with `sentence-transformers/all-MiniLM-L6-v2` embeddings.
- **On-Demand Scraper & Ingestor:**
  - For each distinct `cwe_id` flagged by Agent 1, check if the vector store already contains documentation.
  - If missing, scrape the official MITRE CWE definitions and threat models, chunk the text, and store it into ChromaDB under collection `threat_intelligence`.
- **Context Injection Node:**
  - Retrieve the top 3 relevant sections for each identified CWE (`temperature=0.1`).
  - Attach this contextual mitigation and exploit data directly to `rag_context` in the LangGraph state.

#### 🚀 Phase 4: Dynamic Test Fixture Generation & Docker Sandbox Harness

**Objective:** Synthesize self-contained test scripts and dynamically validate true exploitability.

##### 4.1 Critic Agent (Phase I: Triage & Phase II: Test Generator)
- **Triage Pruning:** Inspect the extracted snippet against the retrieved internal framework context. If framework sanitization handles the vulnerability, mark it `SECURE` and prune it from execution.
- **Fixture Synthesis (`temperature=0.0`):** Extract the unmodified target function and wrap it into an isolated test harness (e.g., in-memory SQLite, mocked API headers, local memory bounds).

##### 4.2 Docker Sandbox Execution & DAG Feedback Loop
- Container dispatch executes the Python/Node.js fixture in an isolated environment.
- Capture execution exit codes:
  - `VULNERABILITY_CONFIRMED`: Payload bypassed checks or accessed forbidden state -> Passed to Senior Analyst.
  - `SECURE`: Payload neutralized cleanly -> Discarded as false positive.
  - `HARNESS_ERROR`: Syntax or import error in the generated fixture -> **DAG loops back to Critic Agent** with `harness_error_traces` to correct the script (bounded by `retry_count <= 3`).

---

#### 🚀 Phase 5: Senior Analyst Remediation & Microsoft Word (.docx) Report Generation

**Objective:** Compile verified findings and export a formatted `.docx` audit document.

##### 5.1 Senior Analyst Agent (`temperature=0.4`)
- Ingests **only** the `VULNERABILITY_CONFIRMED` entries and their associated sandbox runtime outputs.
- Synthesizes root-cause explanations, targeted remediation advice, and side-by-side git diff suggestions.

##### 5.2 Word Document Generation Service (`python-docx`)
- Implement `backend/services/report_generator.py` using `python-docx`:
  - **Cover Page / Header:** Project name, audited branch, timestamp, and authors (Darshil Mendapara & Dhruv Parsana).
  - **Executive Summary:** Scan metrics (total alerts, pruned false alarms, confirmed vulnerabilities).
  - **Detailed Findings Table:** CWE ID, Severity, Affected File & Line Number.
  - **Execution Proof:** Exact test payload used and Docker sandbox execution logs.
  - **Senior Remediation Section:** Safe code patches and defense-in-depth suggestions.
- Expose endpoint `GET /api/report/download?session_id=<ID>` returning a `application/vnd.openxmlformats-officedocument.wordprocessingml.document` stream.

#### 🚀 Phase 6: Next.js Real-Time Animated DAG Dashboard (React Flow)

**Objective:** Provide a visual interactive execution graph showing live node states and results.

##### 6.1 React Flow DAG Visualizer
- Implement visual nodes in Next.js using `@xyflow/react` (React Flow):
  1. `GitHub Ingest (Read-Only)`
  2. `Candidate Discovery Agent`
  3. `Constrained Vector RAG`
  4. `Critic Triage & Fixture Generator`
  5. `Docker Sandbox Execution`
  6. `Self-Healing Loop (HARNESS_ERROR)`
  7. `Senior Remediation Compiler`
  8. `VerifyFix Dashboard (Final Report)`

##### 6.2 Real-Time SSE Animation States
- Hook into the Flask SSE stream:
  - **Idle State:** Light grey borders.
  - **Running State:** Pulsing blue border with active spinner.
  - **Confirmed Vulnerability:** Red highlight with badge counter.
  - **Secure / False Alarm Discarded:** Green checkmark badge.
  - **Looping State:** Orange directional pulse along the feedback edge returning from Docker Sandbox to Critic Agent.
- Provide a side panel displaying live terminal logs, the list of confirmed CWEs, and the "Download Word Report" button upon completion.
